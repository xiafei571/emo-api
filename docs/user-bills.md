# 用户详细账单

仅管理员在「用户 → 操作 → 详细账单」查看指定用户的账单。普通用户没有账单入口或查询接口。

支持今天、近一个月、近三个月、近半年，以及最长六个月的自定义日期。日期包含首尾两天，按选定的 IANA 时区划分自然日，支持夏令时。账单包括：

- 每日各模型的输入、输出、总 tokens，以及实际扣费、退款、净费用。
- 每日及周期各模型的历史输入、输出、缓存读取、缓存写入（含 5 分钟、1 小时）美元/M 单价，含请求当时的分组或用户专属折扣。同一天存在不同单价时展示最小值至最大值，不以混合平均价替代输入/输出单价。
- 周期内各模型汇总与全周期汇总。无消费的日期不生成用量行。
- 周期内及累计的付费充值额度、兑换码额度，周期充值明细，以及生成时的当前钱包余额。
- 可下载的 CSV，包括账户和周期信息、用量、费用及充值明细。

金额为美元计费额度，以 quota / QuotaPerUnit 换算。消费费用使用保留的原始消费日志，不使用模型当前价格重算。退款按退款发生日计入，因此某一天的净费用可能为负数。订阅消耗也包含在用量中，不能用总消费直接推算钱包余额。

付费充值按成功订单的完成时间入账，查询不受原充值历史接口的 30 天限制。Stripe 使用 Money 作为充值额度；Creem 的 Amount 为原始 quota；其他渠道的 Amount 为美元额度。兼容没有 payment_provider 的旧 Stripe/Creem 订单。金额为零的订阅购买订单不计入钱包充值。兑换码使用已兑换记录，包括软删除记录，不导出兑换码密钥。

账单只统计仍保留的记录。已经物理删除的日志或充值/兑换码记录不能恢复；关闭消费日志时会显示不完整提示。赠送额度、邀请奖励及管理员手工调整不计入付费充值。当前余额读取账户数据，不是历史周期末余额。消费库和账户库可分离，因此账单不承诺跨库原子快照。

单价从消费日志的历史倍率换算，退款不产生新单价。动态计费从日志保存的表达式及实际命中档位提取线性 token 单价，再应用历史分组折扣，不重新运行时间条件。缺少元数据、按次计费、重复档位、非线性或含未保存请求倍率的表达式不推算 token 单价，单价列显示 `—`，并统计未提供历史 token 单价的请求数。CSV 增加上述六个价格/M 列及缺少历史单价的请求数列。

## API

- `GET /api/user/:id/bill`：管理员，遵守现有目标角色权限限制。

查询参数：`start_date=YYYY-MM-DD`、`end_date=YYYY-MM-DD`、`timezone=Asia/Shanghai`。未指定时区默认 Asia/Shanghai。无效范围或时区返回 400，越权返回 403。成功响应为 `{success: true, data: UserBill}`。

实现无需数据库迁移。消费记录流式读取，在内存中按天及模型汇总，避免一次装载半年所有请求；汇总 quota/tokens 使用 int64。CSV 对用户、模型和订单等文本做转义，并防止电子表格公式注入。

缺少历史输入／输出单价时，页面和 CSV 显示带明确标注的综合参考均价（扣费 quota / QuotaPerUnit / 记录的输入加输出 tokens × 1,000,000），并增加综合均价列。此值包含缓存、工具或按次费用；Claude 独立报告的缓存 tokens 可能不在分母中，不能与官方输入／输出价直接比较。退款不参与计算；零 tokens 不推算价格。缺少缓存单价显示“未单独记录”，不以综合均价冒充缓存价格。
